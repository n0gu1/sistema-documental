En particular, no se recibieron contraseñas de prueba: no se ejecutó navegación autenticada ni se verificaron bytes del almacenamiento. ## Hallazgos y trazabilidad

**D1 — Alta: autorización de escritura desconectada del catálogo.** `documentos/document_views.py:51` define `WRITE_PERMISSION='documentos.gestionar'`; lo exigen creación (536), modificación (621), eliminación (665), ACL (682/686), archivo (725) y carga (761). Neon devuelve cero filas para ese código. El Editor tiene `documentos.crear`/`documentos.modificar`, que estos endpoints no evalúan. Administrador pasa por el bypass de `auth_utils.user_has_permission`; los demás no obtienen escritura por los permisos configurados. No se reprodujo un POST autenticado; el defecto está comprobado mediante código + catálogo real.

**D2 — Alta: no se pueden guardar concesiones documentales.** `DocumentPermissionsPanel.jsx:47` hace PUT a `permissions/`; `DocumentPermissionsView:704` inserta `asignado_por_id, asignado_en`. Neon tiene `concedido_por_id, concedido_en`. Un conjunto no vacío llega a columnas inexistentes y debe fallar en DB con este código/esquema. No se provocó el fallo en producción. La transacción evita conservar el DELETE si falla INSERT. El payload de consulta sí usa columnas existentes; ver el panel no prueba que se puedan guardar permisos.

**D3 — Alta, condicionada a habilitar gestión: cambio de ACL sin autorización de objeto.** `DocumentPermissionsView.get_document:675` filtra organización, pero no usa `has_document_permission` ni área. Un no administrador al que se conceda `documentos.gestionar` podría editar ACL de cualquier documento activo de su organización. Actualmente ese permiso no existe y D2 impide insertar concesiones; aun así, corregir solamente esos problemas abriría esta vía. No se demostró explotación con los roles actuales.

**D4 — Alta: descarga de no lectores sin permiso específico.** `DocumentFileDownloadView:1109` exige consultar. Solo la rama `is_reader_user` valida `documentos.descargar`. La rama Editor/Revisor usa `get_document_file_or_404`, que verifica acceso de consulta/gestión y pertenencia del archivo, pero no permiso de descarga. La ruta alternativa `DocumentVersionDownloadView:1124` repite el problema. Retirar la descarga global o restringirla por documento no asegura que esos roles dejen de obtener el archivo. No se retiraron permisos en Neon para explotar el caso.

**D5 — Media: contrato de vigente/descarga roto en listado general.** `serialize_document:234` devuelve estado pero no `version`; `documentApi.js:normalizeDocument` deriva `version`, `versionData` y `downloadUrl` de `document.version`. `EditorDocumentsView.jsx:473` termina en «No hay versión descargable» aun cuando Neon tiene archivos. El detalle sí incluye `files` y el serializador lector sí incluye `version`. No es ausencia de archivos demostrada, sino incompatibilidad del contrato.

**D6 — Media: edición parcialmente persistida ante error.** `DocumentDetailView.patch:647` guarda datos antes de `save_metadata` y de subir archivo, sin transacción que cubra todo. Ejemplo: título válido + metadato inválido devuelve error tras haber guardado el título; fallo de almacenamiento también puede dejar edición parcial. `save_document_file` sí intenta borrar el objeto si falla su propia transacción, pero ese manejo no garantiza compensación de una falla posterior al retornar a la transacción externa de creación. No se indujeron errores ni se afirmaron objetos huérfanos reales.

**D7 — Media: código archivado y unicidad incompatibles.** Prevalidación en creación/PATCH excluye eliminados, pero Neon conserva UNIQUE `(organizacion_id,codigo)` global. `TEST-D88C359-NOFILE` es un ejemplo real de código eliminado que sigue reservado. Usarlo para otra alta puede generar error DB no convertido a conflicto legible. No se intentó crear un duplicado.

**D8 — Media: ACL sin denegación explícita.** `reader_access.py:has_document_permission` usa concesiones por permiso; si no queda ninguna para ese documento/permiso vuelve al permiso global y área. Vaciar las casillas puede ampliar acceso, en vez de revocarlo. Administrador está exceptuado; el creador puede superar restricción de área en el fallback. Esto debe ser explícito en UI y requisitos. Neon tiene cero ACL: no permite demostrar denegación individual configurada.

**D9 — Media: búsqueda inconsistente y permiso sin efecto.** La rama lectora de `DocumentListCreateView.get:497` pagina publicaciones sin `apply_document_filters`. La biblioteca dedicada sí filtra nombre/tipo/área/estado; fecha está disponible solo por API y con contrato distinto al cliente común. `documentos.buscar` no interviene en ninguno de esos filtros.

## Botones, formularios y persistencia

- El alta del Administrador tiene POST real y los listados consumen endpoints; no se clasificaron como implementados solo por existir botones. No se encontraron arrays mock usados como fuente documental en los flujos revisados; textos de relleno/estado no se consideraron datos persistidos.
- `DocumentsView.jsx:598` conecta Ver y Editar a `onOpenVersions(document.id)`; `Dashboard.jsx:120` usa callback sin parámetro. Se pierde selección y Editar no abre edición de metadatos. Solo se siguió esa conexión, sin auditar gestión de versiones.
- `EditorDocumentsView.jsx:483` muestra «Más acciones» mediante aviso `onAction`, sin menú operativo; no implementa eliminar ni otro endpoint. El Editor dispone de edición/carga desde detalle, pero no del formulario de alta en el listado revisado.
- Para usuarios y roles hay endpoints sin interfaz de edición/asignación; ver informe 01. En documentos hay backend DELETE/archive sin acción conectada en las pantallas revisadas.
- La eliminación documental revisada es lógica y no borra archivos/versiones. La fila archivada de Neon conserva el registro. Las FK RESTRICT de versiones protegen frente a borrado físico directo del documento; no se hicieron DELETE reales.
- Cargas validan extensión, MIME, firma, tamaño y seguridad básica de ZIP OOXML; luego guardan objeto y registro. Esta existencia de código no prueba persistencia remota. No se inventó un archivo perdido a partir de una fila sin archivo: el backend permite crear documento sin adjunto.
